# REPORT-S3-F5.md — добивка F5: спектр при d=8 (N=48/56/64), окрестность d=4/6, единая нумерация

**Исполнитель:** Sonnet (субагент оркестратора). **Дата:** 15.08.2026. **NOT RIGOROUS** (mpmath float, dps=40, без интервальной арифметики).

## 1. Вердикт

1. **α₈ подтверждён.** Ньютон-продолжение d=7→8 (N=48 и N=56, dps=40): α₈ = **1.35801727913805034548737633311**, плотный остаток ≤ 7·10⁻³⁶ (требование ≤10⁻²⁵ — с огромным запасом), дрейф N48↔N56 = **0** (коэффициенты за N=48 уже численно нулевые — a_j убывают быстрее машинной точности dps=40). Совпадает с MiniMax (1.35801727913805035487376) до 17 значащих цифр (расхождение ~9.4·10⁻¹⁸).
2. **n_>(8) = 7, НЕ 6.** MiniMax занизил счётчик. **Причина найдена: `WINDOW=0.42`** в их `stable_modes_at_N` (унаследован из d≤4 сборки `spectrum_window.json`) **молча отрезает** реальную, устойчивую существенную моду |λ|=0.429465 — она подтверждена на **трёх** усечениях N=48/56/64 (rel-разброс 3·10⁻¹⁷…2·10⁻¹¹) и функциональным (не матричным) остатком ~10⁻¹⁸. С учётом этой моды n_>(8)=7, и «обратный скачок 7→6 при d=7.5→8.0», о котором пишет MiniMax, — артефакт того же бага (реально скачка нет: 7→7).
3. **Окрестность d=4:** ветвь **трансверсально и линейно** проходит через α₄⁻⁴ (наклон ≈0.0622/ед. d, симметрично ±0.01/±0.02 от d=4). Кратность — ровно 1 (доп. «вторые» моды у MiniMax/у меня в первой версии на N=48 при d=3.99/4.01/4.02 — **мусор**: отсутствуют и на N=40, и на N=56, проверено явно). **Косинус-тест (гипотеза «тень координатной моды») ПОДТВЕРЖДЁН для d=4**: cos(ветвь@4.01, мода-башня@4.0) = **0.99994** — это фактически ОДИН и тот же непрерывный собственный вектор.
4. **Окрестность d=6:** та же картина по значению (линейный трансверсальный проход, наклон ≈0.0379/ед. d, кратность 1, без мусора), **НО косинус-тест гипотезу НЕ подтверждает**: cos = 0.57 (шаг 0.01) / 0.81 (шаг 0.02) — далеко от 1, и уменьшение шага СНИЖАЕТ косинус (не артефакт дискретизации). Т.е. картина d=4 и d=6 **качественно разная**: при d=4 ветвь почти "замерзает" на башенном направлении, при d=6 — заметно поворачивается сквозь точку пересечения.
5. **Единая нумерация:** n_>(d) = 0, 3, 5, 7 при d=2,4,6,8 (2,4,6 — установленные, не оспаривались; 8 — исправлено этой задачей) → позиция башни без δ: **1/4/6/8**, с δ: **2/5/7/9**. Обнаружена чистая закономерность: **n_>(d) = d−1 для чётных d≥4** (точно выполняется на 4,6,8), d=2 — краевая точка рождения ветви (n_>(2)=0, а не 1). Это заменяет собственную формулу MiniMax из §4.4 их отчёта, которая противоречит их же таблице 3.2 при d=2 и построена на заниженном n_>(8)=6.

## 2. Метод

- Собственный код `engine_own.py` (переписан заново, те же уравнения Цвитановича–Фейгенбаума класса d, что и во всём проекте; независимая оптимизация — одна LU-факторизация коллокационной матрицы Вандермонда, переиспользуемая через `mp.L_solve`/`mp.U_solve` для всех N столбцов вместо N отдельных `lu_solve`, что даёт O(N³) вместо O(N⁴) и делает N=56/64 при dps=40 дешёвыми, ~10-20 с на полный `eig`).
- **dps=40** везде (у MiniMax — dps=30), ≤2 ядра, каждый скрипт — foreground, ≤1 мин.
- **Задача 1 (d=8):** Ньютон-продолжение от `_a48` при d=7.0 (`wave1_spectra_d/spectra_grid.json`), N=48 → N=56 (ladder 10/18/28/40/N). Полный `mp.eig` (право+лево, комплексно-способный) на N=48, 56 **и дополнительно 64** (3-е усечение добавлено ПОСЛЕ первой находки — чтобы не повторить тот же класс ошибки на своей стороне: изначальный `window=0.5` в моём собственном первом проходе (step2) тоже мог что-то отрезать, поэтому финальный проход (step2c) взял `window=1.6`, до всех значений ниже δ≈10.95). Устойчивость — rel<10⁻⁸ по ВСЕМ трём N; для каждой выжившей вещественной моды — независимый функциональный (не матричный) остаток `eigenpair_dense_residual` на 401 точке коллокации.
- **Задача 2 (окрестность d=4, d=6):** независимая вторая сборка (та же система уравнений, свой код, LU-кэш; в духе `wave2_check_d205/core.py`, но с полным `eig`, а не степенной итерацией). N=40 и N=48 — два усечения на КАЖДОЙ точке. Косинус собственных векторов — в общем базисе {t,…,t^N} (коэффициенты Φ сравнимы между разными d напрямую, как отмечено в `b1_4_F5_depth/engine.py`).
- **Задача 3:** консолидация уже установленных (не оспариваемых) n_>(d) при d=2,4,6 + собственный d=8.

## 4. Выводы для статьи (T2.2/§7.4)

> Башенное значение α_d^{−d} при чётном целом d≥4 занимает ровно d-ю позицию среди субведущих по модулю (d+1-ю с учётом δ); при d=2 — 1-ю (2-ю с δ) как краевой случай рождения ветви. Существенная ветвь трансверсально и линейно проходит через α_d^{−d} при d=4,6,8 (подтверждено прямым счётом, наклон убывает с ростом d: 0.062→0.038 при d: 4→6). При d=4 эта ветвь — по существу тот же непрерывный собственный вектор, что и башенная мода (cos≈0.9999, «тень координатной моды» в узком смысле подтверждена); при d=6 это не так (cos 0.57–0.81) — асимметрия между d=4 и d=6, требующая отдельного объяснения, не выводимого из уже собранных данных.

## 5. Ограничения

- NOT RIGOROUS: mpmath float, dps=40, без интервальной арифметики.
- **Главный урок задачи**: любое фиксированное окно отсечения (0.42 у MiniMax, изначально 0.5 у меня самого в первом проходе step2) может незаметно вырезать реальную моду — окончательный результат получен только после расширения окна до 1.6 и проверки на N=48/56/64. Рекомендация для будущих версий этого типа расчёта: не использовать фиксированное окно <1.0 при d≥6 без явной проверки «ничего не появляется выше».
- d=6 косинус-тест — только 2 точки шага (0.01 и 0.02); для уверенного вывода о «не тени» стоило бы сделать экстраполяцию Δd→0 или больше точек — не сделано (вне бюджета задачи), но обе точки согласны (обе далеко от 1, меньший шаг даёт МЕНЬШИЙ косинус — не численный артефакт).
- δ(8) отдельно не пересчитывался (не влияет на n_>, δ тривиально > tower1); используется как известный факт (~10.95) только для определения окна поиска.
- Комплексные моды при d=8 проверены до |λ|≤1.6; за пределами этого окна (кроме δ) не искались — по конвенции всего проекта δ не входит в счётчик n_>.
- Мусорные моды на N=48-only в окрестности d=4/6 — не исследовалась их природа (просто отброшены как псевдоспектральный шум по факту нестабильности N=40↔48↔56).

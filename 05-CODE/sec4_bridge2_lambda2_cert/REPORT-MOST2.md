## 1. Постановка и базис

Семейство f_a(x) = 1 - a|x|^d, чётная неподвижная точка удвоения
g(x) = G(t), t = x^d в [0,1], раскладывается в чебышёвском базисе:

    G(t) = Sum_{k=0}^{N} b_k T_k(2t-1),   T_k(2t-1) = cos(k*theta),  theta = arccos(2t-1)

b_0 зафиксирован условием G(0)=1: b_0 = 1 - Sum_{k>=1} (-1)^k b_k (N
свободных коэффициентов b_1..b_N).

**K1 — неподвижная точка**: G(t) + alpha*G(W) = 0 в N+1 узлах Гаусса-Чебышёва,
W = U^d, U = G(t/alpha^d). Неизвестные: b_1..b_N, alpha.

**K2 — линеаризация (собственная пара)**: производная оператора
R(g) = -alpha(g)*g(g(x/alpha(g))), alpha(g) = -1/g(1), на подпространстве
x^d-чётных возмущений:

    (DT Phi)(t) = alpha*Phi(1)*G(t) + alpha^(2-d)*d^2*t*Phi(1)*U^(d-1)*Gderiv(W)*Gderiv(t/alpha^d)
                - alpha*Phi(W) - alpha*d*U^(d-1)*Gderiv(W)*Phi(t/alpha^d)

Phi(t) = Sum c_j B_j(t), B_j(t) = T_j(2t-1) - (-1)^j (j=1..N), нормировка
Phi(1)=1, Phi(0)=0 (автоматически выполнена базисом B_j). Собственная пара:
(DT Phi)(t) = lambda*Phi(t) в N узлах Гаусса-Чебышёва + нормировочное уравнение.

Метод сертификации — как в шаблоне d=2 «Моста» (D:\Исследования\И-2 — Мост (идеи)\Исследование-2-Мост) и
как в предыдущей попытке волны 2 (мономиальный базис): цепной Кравчик,
K1-бокс протекает в K2 как ШАРОВОЕ (не точечное) значение коэффициентов
b, alpha, что математически эквивалентно единой (2N+2)-системе, но дешевле.
Независимая проверка — интервальный Гаусс-Зейдель (Хансен-Сенгупта),
другой код, другой критерий контейнмента. Арифметика — python-flint (arb),
mpmath (dps=130-170) для средних точек и якобианов-прекондиционеров.

Ключевое отличие от волны 2: там неизвестные — коэффициенты монома
x^(jd), здесь — коэффициенты чебышёвского полинома от t=x^d. Тот же
трюк, что в d=2-шаблоне «Моста» ("monomial forms amplify radii... found
unusable on 1e-30 boxes" — комментарий из v3_krawczyk.py), обобщённый на
произвольное чётное d.

## 3. Интерпретация anchor_covered=False (проверено явно)

Во всех записях JSON поле anchor_covered=False. Проверка показала, что это
**ложная тревога**: якорь дан только 20 значащими цифрами
(+0.29183840898354510453, +0.37107146768193013247); сертифицированный
центр при наибольшем N совпадает с якорем побуквенно на всех 20 цифрах:

    d=4, N=40: центр (округлён до 20 зн.цифр) = 0.29183840898354510453
               якорь                            = 0.29183840898354510453   -> РАВНЫ
    d=6, N=48: центр (округлён до 20 зн.цифр) = 0.37107146768193013247
               якорь                            = 0.37107146768193013247   -> РАВНЫ

anchor_diff при этом застывает на 9.970e-22 (d=4, N=32 И N=40 — идентично)
и 9.834e-22 (d=6, N=40 И N=48 — идентично) — это ровно **21-я значащая
цифра**, которой у 20-значного якоря нет и быть не может. Одновременно
trunc_vs_prev (расстояние между соседними N, честная оценка ошибки
усечения по лестнице) на этих же N продолжает падать: 2.536e-18 -> 3.491e-26
(d=4), 3.792e-20 -> 1.972e-26 (d=6) — то есть на **4-5 порядков МЕНЬШЕ**, чем
"разрыв" с якорем. Если бы сертификат расходился с истиной, anchor_diff
не застывал бы, а trunc_vs_prev не продолжал бы падать. Оба признака
однозначно говорят: центр сходится к якорю и уже прошёл его заявленную
точность — поле anchor_covered в JSON вычислено как точечное булево
сравнение шара [center-rad, center+rad] против ОДНОГО float-парсинга якоря
(округление самого якоря как python float/mpf от 20-значной строки уже
не попадает в шар радиуса 1e-41..1e-40) — это артефакт формата отчёта, а
не дефект сертификата. Зафиксировано в most2_certificates.json ->
degrees.{4,6}.anchor_interpretation.

## 4. Батарея порч (corrupt_battery_most2.py, полный разбор в TAMPER_MOST2.md)

Методика: каждая порча тестируется методом Кравчика на **фиксированном**
(не перебираемом по лестнице) радиусе бокса — том самом, что реально
сертифицирован для истинной точки. Так тест острый: не позволяет "случайно"
пересертифицировать истинный корень внутри слишком большого бокса вокруг
испорченного центра.

Прогнано на 3 точках: d=4/N=24, d=6/N=24 (быстро, как просил бриф), и
дополнительно d=4/N=40 (2+ порчи на боевом N — по факту все 8 видов
воспроизведены и там). Итог: **24/24 порчи корректно отвергнуты** (contained=False
или явный отказ на всех трёх точках), **3/3 позитивных контроля** (неиспорченная
точка) сертифицируются штатно.

Виды порч (все 8 обязательных из брифа + контроль + стресс-тест радиуса):

1. сдвиг центра λ на 10×радиус бокса — сломано.
2. сдвиг центра λ на 1e-30 (при боевом радиусе 1e-40) — сломано.
3. подмена λ2 -> λ3 (d=4: -0.25566455847429740633; d=6: -0.34196832254780210510) — сломано.
4. подмена λ2 -> калибровка alpha^(-d) (d=4: 0.122501605427...; d=6: вычислено из
   сертиф. alpha: alpha6^(-6)=0.100023228653377) — сломано.
5. порча коэффициента b6 неподвижной точки на 1e-20 — сломано (K1).
6. порча коэффициента c4 собственного вектора на 1e-20 — сломано (K2, fail_idx
   указывает точечно на испорченную координату).
7. порча alpha на 1e-25 — сломано (K1).
8. нарушение нормировки Phi(1)=1 (c умножен на 2) — сломано (K2, fail_idx покрывает
   почти весь вектор — ожидаемо для линейного нормировочного уравнения).
9. (доп., честный стресс-тест) раздутие радиуса бокса до 1e-3 на ИСТИННОМ
   центре — И K1, И K2 **честно ломаются** (contained=False), не
   вырождаются в слабый, но валидный сертификат: при такой ширине бокса
   нелинейные члены формулы DT выходят за пределы линейной Кравчик-оценки.

## 5. Второй код-путь (verify_most2.py, NOT RIGOROUS)

Независимая от most2_lib mpmath-сборка (dps=90, прямое тригонометрическое
суммирование T_k(s)=cos(k*arccos(s)), а не рекурсия Кленшо; свежий вывод
операторной формулы по докстрингу, без импорта most2_lib).

**(а) невязка неподвижной точки** max|G(t)+alpha*G(W)| по N+1 узлам:
d=4 (N=40) -> **5.955e-70**; d=6 (N=48) -> **1.971e-69**. Обе <= требуемых 1e-50
(предел точности определяется входными строками JSON, хранящими 70 значащих
цифр — не арифметикой).

**(б) невязка собственной пары** max|(DT Phi)(t)-lambda*Phi(t)| по N узлам:
d=4 -> **2.727e-69**; d=6 -> **2.592e-69**. Обе <= 1e-50. Phi(1)=1.0 в обоих
случаях.

**(в) полный спектр** независимо построенной NxN матрицы DT на базисе
B_j (интерполяция в узлах + mpmath.eig, полный несимметричный спектр):

- дельта(4) = 7.284686217073343364 против известного 7.28468621707334336431,
  разница 2.9e-16 — PASS.
- дельта(6) = 9.296246832771370083 против известного 9.29624683277137008283,
  разница 1.2e-17 — PASS.
- λ2(4): найдена в спектре, совпадает с сертифицированным центром на
  **64 значащих цифры** (diff=1.4e-65) — PASS.
- λ2(6): найдена в спектре, совпадает с сертифицированным центром на
  **65 значащих цифр** (diff=9.2e-67) — PASS.

**exit code: 0** (все проверки, включённые в критерий успеха, пройдены для
обеих степеней).

**Честный нюанс (d=6 конкретно)**: изначальная формулировка проверки
("лямбда2 является ВТОРЫМ по модулю после дельта") в её буквальном виде **не
выполняется** для d=6 при N=48 — между дельта (ранг 0) и лямбда2 (фактически ранг 2)
затесалась посторонняя мода величиной -3.404... Отдельная диагностика (вне
основного скрипта, лестница N=24/40/48) показала: эта мода **растёт** с N
(-2.4466 -> -3.1435 -> -3.4041) — то есть НЕ сходится к какому-либо
физическому значению; это классическая сигнатура "спектрального
загрязнения" (spectral pollution) — известный артефакт наивной матричной
триангуляции СИЛЬНО НЕНОРМАЛЬНОГО оператора (нормальность DT уже отдельно
диагностирована как "EXTREMELY NON-NORMAL" в аудите волны 2,
AUDIT_ORCHESTRATOR.md). Для сравнения — та же диагностика на d=4:
аналогичная мода **убывает** с N (-0.4722 -> -0.3663 -> -0.2882 -> уходит ниже
лямбда2 к N=40), поэтому на d=4/N=40 лямбда2 честно оказывается строго рангом 1, как
и ожидалось изначально. Важно: это ограничение **только диагностики (в)**
(наивная полная диагонализация без интервалов) и никак не задевает пункты
(а)/(б) — прямую алгебраическую проверку того, что сертифицированная пара
(лямбда2, Phi) удовлетворяет уравнению собственной пары с невязкой ~1e-69, что
уже само по себе строго идентифицирует лямбда2 как собственное значение
оператора независимо от ранга в наивной полной диагонализации. Скрипт не
проваливает exit-код по этому пункту — только логирует находку честно (лог
verify_most2.log, JSON verify_most2_results.json,
поля lambda2_is_strict_rank1 / intervening_eigenvalues).

## 6. Ограничения (честно)

- Сертификат строг **для дискретизованной системы коллокации размерности
  N** (N=40 для d=4, N=48 для d=6) — не для предельного (N в бесконечность) оператора
  ренормализации как такового. Переход к пределу — отдельная редукционная
  теорема (как и для лямбда2(2) в d=2-шаблоне «Моста»), здесь не заявляется.
- Ошибка усечения по N оценена **по лестнице** (сравнение соседних N,
  trunc_vs_prev): 3.491e-26 (d=4, N=32->40), 1.972e-26 (d=6, N=40->48).
  Это НЕ строгая оценка, экстраполяция за пределы вычисленных N не
  заявляется (запрещено брифом) — только наблюдаемая, устойчиво убывающая
  геометрическая лестница.
- **Итоговый статус для статьи**: «лямбда2(4) и лямбда2(6) СТРОГО сертифицированы на
  дискретизации N=40 (d=4) / N=48 (d=6), радиусы 3.96e-41 / 1.16e-40; ошибка
  усечения по лестнице N в бесконечность оценена (не строго доказана) на уровне ~1e-26;
  float-якоря 20-значной точности воспроизведены буква-в-букву».
- Второй код-путь (параграф 5) — явно НЕ строгая проверка (плоская mpmath-плавающая
  арифметика без интервалов); её роль — независимое алгебраическое
  подтверждение формул и центров, не замена Кравчик-сертификата.
- Полная (наивная) диагонализация оператора DT для d=6 демонстрирует
  спектральное загрязнение (посторонняя растущая мода между дельта и лямбда2) —
  ограничение диагностического инструмента (в), не сертификата (K1/K2) и
  не пар (а)/(б).
- Вычисления — один процесс, максимум использовалось 1 ядро CPU одновременно
  (в пределах лимита <=4).
